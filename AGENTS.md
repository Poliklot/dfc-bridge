# Documentation narrative

- Read `CONTRIBUTING.md` before changing explanations. Its editorial sequence applies to all authored documentation and all three locales.
- Explain prerequisites, selection/scope, action, expected result and next step. Keep requirements, examples, proposals and verified behavior distinct.
- Preserve technical identifiers and rule meaning across EN/RU/ZH. Never translate schema keys or invent tags to make prose shorter.
- Edit canonical sources, not generated site content. A passing test is not proof that the narrative or translation is clear.

# Tutorial media

- Before creating or changing tutorial screenshots, recordings, crops, captions, media renderers, provenance or documentation embeds, read `assets/tutorial/MEDIA-PRODUCTION.md` and `assets/tutorial/README.md`.
- Use real Figma evidence. A screenshot sequence is not a continuous recording; generated or redrawn editor UI is not evidence.
- Preserve the original teaching file and its deliberate diagnostic examples. Perform recording edits in a disposable QA copy.
- Stage media before replacement. Mechanical checks and manual playback/readability review are separate requirements; report only checks actually run.
- Never restamp old captures as new or claim that older clips satisfy a newly introduced recording standard without inspecting their source timeline.
