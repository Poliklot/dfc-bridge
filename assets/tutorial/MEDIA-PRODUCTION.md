# Как делать понятные скриншоты и видео DFC Bridge

Обязательный порядок работы для человека и ИИ, включая модели, которым нужны точные шаги. Применяется к учебным материалам этого репозитория. Это инструкция производства, **не отчёт о том, что все существующие материалы уже соответствуют каждому пункту**.

**Цель:** зритель видит исходное состояние, конкретное действие в настоящей Figma и проверяемый результат. Не просто красивый ролик, быстро сменяющиеся картинки или финальный экран.

## 1. Сначала определить факт, затем снимать

1. Прочитать [описание учебного файла](README.md), соответствующее место урока и правило методологии. Для этого набора: [адаптивы](../../docs/03-responsive-breakpoints.md), [контракт передачи](../../docs/04-transfer-contract.md) и [русский урок](../../docs/ru/25-vizualnyj-urok.md).
2. Записать одну фразу: «После этого фрагмента зритель сможет ___». Указать ровно тот факт, который будет виден. Например: «переименовать слой, не меняя текст внутри него».
3. Записать начальное состояние, действие и ожидаемое конечное состояние. Отдельно — что менять нельзя. Использовать сценарии в разделе 5.
4. Проверить настоящую Figma: нужный файл, страницу, выделенный узел, его родителя, свойства и текущие значения. Не считать устаревший скриншот или JSON доказательством текущего UI.
5. Сначала пройти действие без записи на отдельной QA-копии. Узнать точный контроль, который его выполняет. Затем восстановить начальное состояние только в этой QA-копии и проверить его снова.
6. Выбрать доказательство: скриншот — для состояния и сравнения; непрерывное видео — для действия. Не заменять запрошенный процесс тремя картинками.

### Карточка одного фрагмента

Заполнить до записи; пустые пункты означают, что снимать рано.

```text
ID: rename-title
Факт: меняется идентичность слоя, не продуктовый текст
Файл / QA-страница / узел: фактически проверенные значения
До: слой Title mobile; текст «Мастерская макетов»
Действие: войти в редактирование имени, набрать hero-title, подтвердить
После: слой hero-title; текст по-прежнему «Мастерская макетов»
Не менять: текст, родителя, Auto Layout, исходный учебный .fig
В кадре: редактируемое имя, необходимая часть дерева и сам заголовок
Паузы: до действия ≥ 2 с; после подтверждения ≥ 3 с
Подписи RU / EN / ZH: короткий факт, без нового обещания
Способ ввода: настоящие нажатия по символу; не вставка всей строки
Что НЕ доказывает: исправление текста, Ready, готовность приложения
```

## 2. Не смешивать виды материалов

| Материал | Что это | Чего нельзя о нём говорить |
| --- | --- | --- |
| Скриншот редактора | Реальный захват Figma, при необходимости один прямоугольный кроп | «Экспорт узла», если захвачен редактор; «новый захват», если изменён только кроп |
| Экспорт узла | PNG настоящего native-узла через Figma | «Скриншот редактора» или «доказательство нажатия» |
| Непрерывная запись | Один непрерывный интервал реального видео при исходной скорости | «Непрерывная», если собрана из PNG, разных дублей или дополнена искусственными паузами |
| Пошаговая последовательность | Монтаж отдельных реальных состояний | «Запись процесса»; в этом репозитории старые v2 остаются историческими последовательностями |
| Диаграмма / персонаж | Редакционное объяснение / иллюстрация | «Нативное доказательство», «настоящая переписка команды» |

Нельзя генерировать, перерисовывать, дорисовывать или склеивать интерфейс Figma для доказательства. Нельзя подменять промежуточные состояния через API и выдавать это за ввод человека. Разрешена автоматизация **настоящих UI-действий** с честным описанием способа ввода. API допустим для подготовки QA-копии до дубля и для проверки свойств после него, но такая подготовка не считается снятым действием.

Два настоящих кропа можно поставить рядом в HTML с отдельными подписями. Это сравнение двух изображений, а не один якобы цельный скриншот.

## 3. Подготовить безопасное и читаемое окно

1. Работать только с собственным учебным файлом или разрешённой одноразовой QA-копией. Не снимать клиентские файлы, переписку, токены, чужие вкладки и уведомления.
2. Сохранить исходную учебную копию. Не исправлять сохранённую диагностическую страницу и не заменять `.fig` ради удачного дубля. Рабочие страницы для записи не включать в пятистраничный учебный архив без отдельной задачи.
3. Открыть нужную страницу. Удалить из кадра всплывшие меню, tooltip, toast и результаты предыдущего действия, если они не являются предметом обучения. Дождаться загрузки UI, шрифтов и плагина.
4. Настроить **до записи** размер окна, ширину панели, раскрытое дерево и zoom Figma. Нужный текст должен читаться в исходном захвате. Увеличение размытого фрагмента после записи не создаёт детализацию.
5. Оставить в кадре контроль действия и достаточно контекста, чтобы было понятно, к чему он относится. Для переноса нужен родитель и обе кнопки; для локальной цели — исходный экземпляр и контекст цели. Не снимать всё окно, если 80% его площади не относится к уроку.
6. Проверить прямоугольник будущего кропа на всём пробном действии: открывшееся поле, dropdown, конечный узел и важные метки не выходят за край. Кроп не должен обрезать фокус, рамку выбранного слоя или символ тега.
7. Оставить настоящие поля вокруг предмета. Для скриншота не дорисовывать поля в пикселях; внешние HTML-поля — отдельное оформление. Для видео редакционная подложка и полоса подписи могут находиться вне native-области.

Если в одном кадре нужные доказательства слишком далеко друг от друга, сначала перестроить рабочее окно/панели. Если это не помогает — разделить учебные факты на самостоятельные явно названные записи. Не склеивать два состояния и не двигать виртуальную камеру, выдавая монтаж за непрерывную операцию.

## 4. Записать настоящее действие

### Локальный рекордер

Из корня репозитория:

```sh
node scripts/serve-figma-recorder.mjs
```

1. Открыть `http://127.0.0.1:4393` в браузере с поддержкой `getDisplayMedia` и `MediaRecorder`.
2. Нажать **Start**. В системном выборе источника выбрать **только окно учебной Figma**, не весь экран и не вкладку. Рекордер отклоняет источники, не сообщающие `displaySurface: window`.
3. Убедиться, что рекордер показывает **Recording the selected surface**, а не ещё открытый выбор источника. Вернуться в Figma и снова проверить кадр: поднятие окна может изменить видимую область холста. При необходимости заново выделить предмет и выполнить **Zoom to selection (Shift+2)**. Подготовка должна закончиться до полезного интервала. Затем записать стабильную паузу «до»; переключения и подготовку позднее обрезать только с начала/конца.
4. Выполнить один подготовленный сценарий. Записать паузу «после». Вернуться к рекордеру и нажать **Stop**.
5. Нажать **Save WebM**, затем **Save capture metadata**. Проверить, что оба файла действительно появились в загрузках и что WebM воспроизводится. «Save requested» — не подтверждение наличия файла на диске.
6. Сверить имя WebM, размер в байтах и SHA-256 с сохранённым JSON. **Clear нажимать только после проверки обоих скачанных файлов:** кнопка удаляет запись из памяти страницы. Только после этого можно начать следующий дубль. Не очищать и не закрывать страницу, пока сохранение не подтверждено.
7. Сохранить исходный WebM и JSON вне публикуемых assets. Записать дату, часовой пояс, файл/страницу/узел и способ ввода отдельно. Не загружать исходное окно в репозиторий до проверки приватности.
8. Остановить сервер через Ctrl+C после работы. Не запускать второй сервер поверх занятого порта и не завершать неизвестный процесс.

Рекордер слушает только `127.0.0.1:4393`, не загружает запись на сервер и не записывает микрофон/системный звук. Он запрашивает 30 fps и native-курсор, но запрос **не гарантирует** фактическую частоту или сопровождающий действия курсор. Проверить сам файл. Metadata содержит SHA-256, настройки и длительность по `performance.now()` от запуска до запроса остановки. Это **не журнал времени каждого клика/символа** и не замена decoded PTS видео. WebM может иметь переменную частоту кадров или не иметь общей длительности в контейнере; проверять временные метки декодированных кадров.

**Проверка самого raw обязательна.** Сразу после пробного дубля воспроизвести сохранённый WebM и извлечь кадры до действия, во время него и после. Проверить, что в **декодированном видео**, а не только в скриншоте CUA или accessibility-дереве, видны предмет и контролы. В этой среде уже встречалось: CUA показывал кнопку по центру, а запись окна — кнопку за правой панелью. Такой дубль отклонить и переснять; верные значения свойств вне кадра не заменяют видимого результата. Пример извлечения одного кадра (пути и время заменить фактическими):

```sh
ffmpeg -i /absolute/path/to/take.webm -ss 3.0 -frames:v 1 /tmp/take-at-3s.png
```

Размеры и таймкоды брать из фактического видео, не только из начальных `track.getSettings()` рекордера. Метаданные и screenshot могут не отражать последующее изменение окна.

### Если действия выполняет UI-автоматика

- Перед кликом поднять нужное окно и проверить его актуальное UI-состояние. Первый клик по фоновому окну может только дать ему фокус. Не считать его выполненным действием без проверки результата.
- Для индексов accessibility-контролов брать новое дерево после каждого действия и скриншота. Не повторять устаревший индекс. Сопоставлять конкретный контроль и текущее значение, а не первую похожую строку.
- После **Start** проверить статус рекордера. Не нажимать Start второй раз вслепую, если открывается системный выбор или запись уже идёт.
- Для `State` открыть настоящий dropdown и выбрать видимый пункт `hover`; нажатие стрелки не гарантирует изменения значения. Проверить значение **и внешний вид кнопки**.
- Внутри удачного дубля выполнить заранее проверенную короткую последовательность с нужными настоящими паузами. Не оставлять по 10 секунд ожидания ответа модели между простыми шагами. Пауза для чтения допустима, поиск ошибочного контрола — причина переснять.
- Установка значения через API, `fill` или мгновенную вставку не превращается в набор от добавленной подписи. Проверять реальные символы и промежуточные кадры.

### Темп и видимость — обязательны для новых дублей

- Перед первым действием — не менее **2 секунд** настоящего стабильного состояния.
- После подтверждённого результата — не менее **3 секунд** настоящего стабильного состояния. Если надо прочитать длинное значение, дать больше времени.
- Текст вводить по символам с интервалом **100–160 мс**. Сначала показать вход в правильное поле. Должны быть видны растущая строка и подтверждение. Не использовать `fill`, мгновенную вставку строки или прямую запись свойства как замену посимвольному вводу.
- Проверить раскладку клавиатуры на коротком пробном вводе в QA-копии. Метод `typeText` или название инструмента сами по себе не гарантируют правильные символы: проверить фактическую растущую строку в UI и raw-видео. При неправильной раскладке исправить ввод и начать новый дубль; не заменять его скрытой вставкой с подписью «набрали».
- Для длинного китайского или иного текста использовать реальный поддерживаемый UI-ввод и проверить результат; не выдумывать, что конкретный инструмент умеет посимвольный ввод. Если доступна только мгновенная вставка, записать и раскрыть именно вставку или остановиться и выбрать другой реальный способ — не назвать её набором.
- Настоящие **Cut → выбор существующего родителя → Paste** допустимы для переноса группы. Прямо сказать это в описании. Не называть Cut/Paste перетаскиванием; не анимировать фальшивый указатель по придуманной траектории.
- Если native-курсор не следует автоматическим действиям, сказать об этом. Для внимания можно добавить тонкую пустую обводку вокруг настоящего контрола. Не рисовать курсор, клик, печатающиеся символы или фон поверх нативного UI.
- Каждая пауза должна иметь цель: прочитать, увидеть исходное состояние, сравнить результат. Убрать ожидание загрузки и поиск нужного пункта пересъёмкой, а не ускорением или внутренней склейкой.
- Не вставлять стоп-кадры, дубли кадров ради удлинения, «плавные» синтетические переходы, интерполяцию, ускорение или замедление. Обычное приведение настоящей временной шкалы к CFR30 при кодировании не является разрешением добавить учебные паузы.

Если обязательные паузы не попали в исходник, **переснять**. Длиннее показываемая подпись не исправит отсутствие настоящего конечного состояния. При этом исторический короткий дубль не становится «соответствующим новым нормам» после перемонтажа подписи.

## 5. Семь сценариев: что показать и что сохранить

Следующие шаги относятся к существующему учебному workshop. Идентификаторы узлов зависят от QA-копии: найти и проверить фактические, а не слепо применять старые.

### `page-metadata` — связать корни

1. До: выбран мобильный корень, Assistant показывает его Page-поля. Если тип Page уже установлен, не заявлять, что клип демонстрирует выбор типа.
2. Показать редактирование имени `workshop`, page `workshop`, route `/workshop`; проверить view `default`, bp `375`. Не притворяться, что неизменённые значения были введены в этом дубле.
3. Подтвердить изменение. Показать переход к соответствующему корню 1440, если это входит в учебный факт, и реальную смену выделения.
4. После: у корней одна страница, маршрут и вид; ширины разные. Настройка тегов не создаёт дизайн, компоненты или код. Не показывать прежнее имя с подписью о якобы уже применённом новом.

### `rename-title` — изменить имя, не текст

1. До: в дереве `Title mobile`, на холсте «Мастерская макетов».
2. Войти в редактирование **имени слоя**, набрать `hero-title` по символам, подтвердить.
3. После: новое имя видно; содержимое осталось «Мастерская макетов». Родитель и Auto Layout не менялись. Не показывать полный текст как результат переименования.

### `repair-copy` — восстановить согласованный текст

1. До: тот же `hero-title`, сокращённое «Мастерская макетов».
2. Редактировать **текстовое содержимое**, а не имя. Набрать «Мастерская понятных макетов», подтвердить и выйти из режима редактирования.
3. После: полный текст читается на холсте; имя и родитель прежние. Это выбранный для примера общий текст, не запрет согласованного продуктового варианта.

### `move-actions` — вернуть всю группу в существующего родителя

1. До: раскрыто дерево `hero`; `hero-actions` находится вне `hero-copy`, непосредственно в `hero`; видны обе дочерние кнопки.
2. Выделить **целый `hero-actions`**, выполнить Cut, выбрать существующий `hero-copy`, выполнить Paste. Не создавать новый wrapper, не переносить одну кнопку, не выбирать случайный узел с похожим именем.
3. После: `hero-actions` — дочерний узел `hero-copy`; обе кнопки сохранены, Auto Layout включён. Дополнительно проверить native-структуру. Cut/Paste может заменить временные node ID — сам факт смены ID не означает ошибку.
4. Объяснять смену значимого родителя, не перестановку соседей внутри одного родителя. Последняя разрешена без объявления структурной трансформации; для согласованного изменения родителя существует отдельная декларация.

### `button-states` — показать appearance и независимый focus

1. До: native-экземпляр связан с настоящим button component set; видны свойства `State` и `Focus visible` и сама кнопка.
2. Изменить состояние через настоящий контроль. Показать независимое переключение `Focus visible`, в том числе совместимость фокуса с другим состоянием, если это видно в дубле.
3. После: native-связь не разорвана. В учебных источниках четыре `State`: `default`, `hover`, `pressed`, `disabled`; focus — Boolean, не пятый взаимоисключающий вариант. Не добавлять отсутствующий loading.
4. Не называть смену свойства реальным hover, клавиатурной навигацией, рабочим disabled или доказательством accessibility. Это образцы внешнего вида; runtime проверяется отдельно.

### `local-action` — действие экземпляра и скрытая локальная цель

1. До: выделен `contact-button` **на странице**, не исходный компонент библиотеки. Проверены корень, page/view/bp и скрытый локальный `contact-modal` внутри нужного корня.
2. Через Assistant выбрать существующую локальную цель; показать полученное `[action=modal:contact-modal]` на экземпляре. Не переносить page-specific действие на общее имя компонента.
3. Нажать **К цели / Show target**. После показать выделение скрытого слоя нужного контекста. Цель остаётся скрытой; это не открытие модального окна и не preview прототипа.
4. Видимый общий источник в Modals не является вторым action-target страницы. Не выбирать цель одноимённой соседней QA-страницы. Для отдельной recording-копии уже использовалось пространство `workshop-recording` / `/workshop-recording`: сохранять или менять его только осознанно, не выдавать его за изменение shipped workshop.

### `repeat-check` — повторно проверить определённую область

1. До: есть настоящее старое сообщение с двумя ошибками по copy и parent. Проверить, какой файл, page/view/bp оно охватывает.
2. Если исправления выполнялись **до начала записи**, явно сказать: «Исправления уже внесены; на экране старый отчёт». Не приписывать этому клипу доказательство процесса исправления.
3. Нажать настоящий **Repeat / Повторить**. Дождаться нового результата; показать числа и область `default`, 375/1440.
4. После: 0 ошибок/черновиков/предупреждений только для проверенной области. Не говорить «приложение готово», «полная QA», «всё доступно» или «библиотека полностью проверена».
5. Исходная диагностическая страница учебного `.fig` сохраняет ровно две намеренные проблемы. Нельзя чинить её ради зелёного результата; исправляется QA-копия.

Это семь **самостоятельных операций**, а не доказательство одного последовательного построения файла. Не объединять результаты разных QA-страниц словами «теперь мы исправили всё».

## 6. Скриншоты: сохранять пиксели, улучшать выбор кадра

1. Установить и проверить состояние в реальной Figma. Сделать исходный захват. Сохранить его без обработки и вычислить SHA-256.
2. Найти минимальный прямоугольник, в котором читаются учебный факт и необходимый контекст. У дерева не срезать значимого родителя; у карточки результата — название проверки и числа; у hero — нужные элементы и имя корня, когда оно часть факта.
3. Сохранить **lossless PNG-кроп без ресайза**, дорисовки, удаления интерфейса, стрелок, номеров и синтетических полей. Не использовать генератор изображений для улучшения screenshot.
4. Если нужны обзор и деталь, сохранить оба отдельными файлами. В подписи детали дать ссылку на полный источник. Не удалять обзор только потому, что деталь лучше читается.
5. Внести факт захвата в `capture-provenance.json`: реальная дата, интерфейс, file key, страница/ревизия, имя исходника, SHA-256 исходника, исходные размеры и точный `{left, top, width, height}`.
6. Для детали из уже зарегистрированного скриншота использовать `derivedFromCapture` и `sourceCaptureFile`, указывающие на его запись, а не придуманный новый raw-захват. Наследовать дату, исходную ревизию, file key и hash учебного архива. `sourceSha256` здесь относится к непосредственному PNG-источнику кропа. Не строить цепочку «кроп из кропа из кропа».
7. Выполнить существующий воспроизводимый сборщик и независимую проверку:

```sh
node scripts/build-tutorial-screenshots.mjs
node scripts/build-tutorial-screenshots.mjs --check
```

Первый вызов **перезаписывает зарегистрированные производные PNG**, не снимает Figma и не генерирует новый UI. Проверка сравнивает decoded-пиксели точного прямоугольника и размеры. Перед сборкой сохранить предыдущие производные вне assets для восстановления, если проверка/просмотр не пройдут. Не менять хеши лишь для того, чтобы «позеленел тест»: сначала выяснить причину отличия.

В текущем наборе 20 исходных зарегистрированных captures и 3 производные детали дают 23 PNG assets. Это **не 23 новых захвата**. Количество размещений в документации, PNG-файлов, исходных захватов и локализованных видео считать отдельно.

## 7. Кроп, подписи и кодирование видео

### Один непрерывный интервал, один фиксированный кроп

- Сначала просмотреть весь raw-файл. Выбрать начало до действия и конец после результата с настоящими паузами. Внутри интервала не вырезать ошибку, ожидание или неудачное действие: переснять.
- Выбрать один постоянный прямоугольник на весь клип. Он должен сохранять необходимый контекст и не выпускать контролы за границу ни на одном этапе. Не скрывать критичный результат слишком тесным кропом.
- Сначала сохранить безопасную выдержку в `motion/source/video/` с документированной связью с локальным original. Сохранить SHA-256 original, его интервал и privacy-crop. Не публиковать весь desktop ради воспроизводимости. До замены excerpt сохранить предыдущий согласованный набор source/storyboard/provenance/derivatives вне assets; не удалять единственную копию исходника. Финальный `motion/source/video/` содержит только семь источников, зарегистрированных текущим storyboard, а не неучтённые старые дубли.
- Координаты `clip.crop` и подсветок относятся к **сохранённому excerpt**, а не автоматически к полному окну. Если есть privacy-crop original и затем subject-crop excerpt, документировать оба прямоугольника и их систему координат; не складывать/смешивать их на глаз.
- Не увеличивать native-пиксели при кодировании. Разрешён downsample с сохранением пропорций. Размер кадра подбирать по предмету, а не заставлять узкую панель занимать маленькую часть обязательного 1920×1080. Для subject-fit использовать итоговые размеры конкретного клипа из manifest; HTML `width`/`height`, poster и GIF должны совпадать с ними.
- Редакционная подпись располагается вне native-области. Только stroke-only обводки реальных контролов допустимы поверх неё: без заливки и маскировки текста. Декоративные персонажи и комментарии не закрывают интерфейс.

### Подписи RU / EN / ZH

1. Одна подпись — одна короткая мысль о том, что видно **в этот момент**. Не обещать результат до его появления.
2. **Для нового дубля** каждой подписи дать время чтения не меньше `max(3 секунд, количество слов / 3)` для RU/EN; для китайской — `max(3 секунд, количество CJK-символов / 5)`. Округлять вверх; технические теги тоже требуют чтения. Для одной общей временной сетки выбрать максимум по трём языкам. Это минимальный ориентир, не замена просмотру.
3. Если подпись длинная, сначала сократить её без потери смысла; подробности оставить в HTML `figcaption`. Не уменьшать шрифт до нечитаемого и не ускорять показ.
4. Последняя подпись объясняет конечное состояние и остаётся на реальных последних кадрах. Не продлевать видео стоп-кадром, чтобы соблюсти норму чтения. Если кадра не хватает — новый дубль или честно ограниченный исторический материал.
5. На маленькой ширине проверить также burned-in текст. Фраза «можно открыть fullscreen» не оправдывает непонятное inline-превью. Если тонкие детали требуют увеличения, основной факт и HTML-подпись всё равно должны быть понятны без него; раскрытие детали должно работать.

**Не путать норму нового дубля с техническим минимумом.** `assertCueReadingTime` проверяет только механический floor `max(1.2, 0.4 + words / 3 + CJK / 7)` секунд, объединяя соседние одинаковые подписи. Этот порог поддерживает и исторические короткие записи; его pass не доказывает ни 3 секунды на новую подпись, ни читаемость. Сохранённые записи `page-metadata`, `rename-title` и `repair-copy` от 12 октября 2026 года получили новые кропы и подписи, но не новые реальные паузы. Не объявлять их соответствующими новому стандарту темпа без отдельного аудита исходного timeline.

### Сборка сначала во временный каталог

#### Из raw-записи в безопасный excerpt

Не начинать со сборщика подписей: он **не записывает Figma**. Сначала проверить raw и выбрать интервал по декодированным кадрам. Ниже конкретный рецепт принятого `local-action` от 13 октября; для другого дубля заново измерить все числа, не копировать их автоматически.

```sh
# Указать фактически сохранённый локальный файл; не публиковать этот путь.
RAW="/absolute/local/path/to/recording.webm"
SANITIZED="/tmp/local-action-reviewed.webm"
shasum -a 256 "$RAW"
ffprobe -v error -show_streams -show_format -of json "$RAW"
ffprobe -v error -select_streams v:0 -show_frames \
  -show_entries frame=best_effort_timestamp_time,width,height,duration_time \
  -of json "$RAW" > /tmp/local-action-raw-frames.json

ffmpeg -hide_banner -loglevel error -n -i "$RAW" \
  -vf 'trim=start=17.5:end=38.1,setpts=PTS-STARTPTS,crop=840:810:0:330:exact=1' \
  -an -c:v libvpx-vp9 -lossless 1 -pix_fmt yuv420p -fps_mode passthrough \
  -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 \
  "$SANITIZED"
shasum -a 256 "$SANITIZED"
ffprobe -v error -show_streams -show_format -of json "$SANITIZED"
```

Здесь исходник уже имел один video stream, `yuv420p`, `tv/bt709/bt709/bt709`; цветовые параметры **описывают проверенный источник**, а не исправляют произвольный цветовой профиль. Если probe показывает другое — остановиться и согласовать реальное преобразование с renderer/checker, не подставлять эти метки. `trim` использует decoded PTS, `setpts` только переносит начало в ноль, `crop` задаёт `width:height:left:top`; нет изменения скорости, ресайза или `fps`-фильтра. Lossless VP9 не отменяет компрессию первоначального захвата. `-n` не перезаписывает существующий файл.

Просмотреть полученный excerpt целиком, проверить приватность каждого края, размеры каждого кадра и длительность по PTS. Только затем скопировать его под новым датированным именем в `motion/source/video/`, а заменяемый excerpt сохранить вне assets. В `native-storyboard.json` заполнить по фактам `sourceCapture` (дата, SHA-256, original hash/интервал/privacy-crop), `trim`, `crop`, `presentationPurpose`, `posterAtSeconds`, `cues` для трёх языков и `auditFrames` с реально видимыми промежуточными значениями. Координаты `crop`/обводок считать уже внутри excerpt. `approved: true` ставить после просмотра, не ради обхода assert. Выходные хеши и размеры создаёт renderer; не редактировать их вручную.

Из корня репозитория, с установленными зависимостями, Node из `package.json`, FFmpeg и ffprobe:

```sh
node --version
ffmpeg -version
ffprobe -version

node scripts/build-native-walkthrough-motion.mjs \
  --clip rename-title --locale ru \
  --output-dir /tmp/dfc-native-review

node scripts/check-native-walkthrough-motion.mjs \
  --output-dir /tmp/dfc-native-review --allow-incomplete
```

Renderer и checker запускают FFmpeg с **`-cpuflags 0`**: scalar-декодирование и преобразование цвета исключают различия округления YUV→RGB между SIMD-путями ARM и x86. Не убирать этот параметр ради ускорения и не заменять точные hash/pixel-проверки допуском. Версии FFmpeg и ffprobe всё равно записывать в локальный отчёт: этот параметр не обещает одинаковый MP4-битстрим для любых версий кодировщика. Если меняется рецепт декодирования, заново собрать весь согласованный набор производных в staging из неизменённых excerpt, проверить его на обеих платформах и просмотреть; не переписывать одни хеши. Это новая производная, **не новая запись Figma**: даты захвата, source/storyboard и связь с original сохраняются.

`--allow-incomplete` допустим **только для просмотра поднабора**, не для принятия полного набора. Проверить RU-пример глазами, затем собрать все языки и действия в тот же staging-каталог:

```sh
node scripts/build-native-walkthrough-motion.mjs \
  --output-dir /tmp/dfc-native-review

node scripts/check-native-walkthrough-motion.mjs \
  --output-dir /tmp/dfc-native-review
```

Сценарии и source-файлы берутся из `assets/tutorial/motion/native-storyboard.json` и `assets/tutorial/motion/source/video/`. Для согласованной альтернативной карточки поддержан `--storyboard /absolute/path/to/native-storyboard.json`; передать **тот же путь** сборщику и checker. Не писать несуществующий `--publish`: сборщик намеренно не публикует поверх assets.

После проверки staged-файлов сохранить резервную копию текущего публикуемого набора вне assets. Заменять согласованно производные в `motion/native/`, proofs в `motion/audit/`, `native-provenance.json`, соответствующий storyboard/source и HTML-размеры/подписи. Не копировать один новый MP4 при старом poster/GIF/manifest. В финальных каталогах не оставлять неучтённые тестовые файлы. До успешной итоговой проверки изменение не считать принятым; при неудаче восстановить весь предыдущий согласованный набор из резервной копии, не через destructive Git-команды.

## 8. Происхождение и честная граница проверки

Для видео хранить: capture date и реальную source-ревизию; QA file/page; исходный original SHA-256 и место его локального хранения; интервал excerpt в original; original privacy-crop; SHA-256 сохранённого excerpt; trim и subject-crop; временные подписи и обводки; реальные before/action/after audit-кадры; renderer/storyboard hashes; hashes, размеры, duration и ссылки всех производных.

Не заменять дату захвата датой кропа, перевода, пересборки или публикации. Если добавлена новая производная, описать это как новую производную старого свидетельства. CI может проверить сохранённый excerpt, его кадры и производные. Если original хранится только локально, **CI не проверяет original**; связь с ним документальная, а не независимо доказанная.

Минимум audit: before, несколько фактических промежуточных действий, after. Для набора текста проверить не менее трёх возрастающих промежуточных значений. Один финальный скрин не доказывает посимвольный ввод. Метаданные рекордера не доказывают интервалы между символами: для этого нужна проверка фактического видео/его PTS.

Новый стандарт темпа применяется к новым дублям. Исторические записи можно улучшить честным кропом/подписями и отметить ограничения, но нельзя автоматически переаттестовать их как соответствующие нормам 2/3 секунд или темпа ввода.

## 9. Проверить два разных качества

### A. Техническая проверка

```sh
node scripts/build-tutorial-screenshots.mjs --check
node scripts/check-native-walkthrough-motion.mjs
npm run lint:tutorial
npm test
npm run test:e2e
```

`npm test` собирает сайт; browser-тесты проверяют собранный `dist`, поэтому не запускать их на устаревшей сборке. **Не пересобирать и не менять `dist` во время browser-тестов:** сборка может удалить обслуживаемые файлы и оборвать preview. Порядок: закончить сборку → запустить preview → закончить browser QA → остановить свой preview перед следующей сборкой. Если задан `PLAYWRIGHT_BASE_URL`, убедиться, что это именно обновлённый preview, а не старый сервер. Для Assistant-регрессии использовать его тесты с `DFC_BRIDGE_METHODOLOGY_DIR`, указанным в [README](README.md), когда изменены native-данные или отчёты Assistant.

Если порт 4322 занят dev-сервером, после успешного `npm test` открыть отдельный терминал и выполнить `PORT=4323 node scripts/serve-dist.mjs`. В другом терминале: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:4323 npm run test:e2e`. Проверить строку `Serving .../dist`, а не `astro dev`: dev toolbar может добавлять служебный DOM, которого нет в публикации. После QA остановить только свой preview через Ctrl+C. Если 4323 тоже занят — выбрать свободный порт и одинаково заменить его в обеих командах.

Зафиксировать фактический вывод, код завершения и что не запускалось. Эти проверки подтверждают только свои инварианты: происхождение, геометрию, timeline, локализацию, воспроизводимость, ссылки, поведение просмотрщика и т. п. Они не умеют решить за человека, понятен ли учебный фрагмент.

`tests/tutorial-quality.spec.mjs` запускает три локализованных playlist-теста: каждый MP4 действительно проигрывается при 1× от начала до естественного конца с pause/resume, без seek и изменения скорости. Ещё 18 тестов проверяют геометрию RU/EN/ZH × 1440/390/320 × light/dark и сохраняют изображения для чтения. Матрица запускается один раз в проекте `desktop`, поскольку сама задаёт мобильные ширины. **Автоматически проиграно целиком** не означает **просмотрено глазами целиком**: в отчёте указать оба результата отдельно. Извлечённые кадры подтверждают только проверенные моменты, не весь движущийся материал.

### Как снять пригодные для чтения browser-QA скриншоты

1. Дождаться шрифтов (`document.fonts.ready`), декодирования изображений и posters. Для видео в этом QA-тесте разрешено временно поставить `preload="auto"` и дождаться `canplay` / `readyState >= 3`, проверяя ошибки и timeout. `loadedmetadata` / `readyState >= 1` доказывает размеры, но не готовность кадра. Даже после `canplay` native spinner может ещё исчезать: для paused poster дождаться трёх последовательных одинаковых реальных снимков figure (проверять каждые 250 мс, не дольше 15 с, с разрешёнными анимациями). Это проверка стабильности пикселей, не произвольный sleep и не отключение браузерного fade. Если снимки не стабилизируются — выяснить причину, не скрывать controls/spinner. Не менять ради теста опубликованную политику preload. Стабильность не доказывает, что spinner отсутствует: итоговый PNG всё равно прочитать глазами.
2. Снимать отдельную законченную figure с её видимым комментарием, медиа и `figcaption`, не весь длинный урок. Для текущей выборки нужны пять самостоятельных целей: desktop hero, mobile hero, `button-states`, `local-action`, `repeat-check`. Два hero на узком экране снимать отдельно, а не обрезать высокую общую группу.
3. После прокрутки проверить фактический прямоугольник: верх figure ниже fixed/sticky header, низ подписи не обрезан. `scrollIntoViewIfNeeded()` само по себе этого не гарантирует. Не скрывать header, controls или loading UI стилями для «чистого» отчёта. Если figure выше viewport, увеличить только высоту окна для полного локального снимка и записать это; проверяемую ширину оставить прежней.
4. Сохранить PNG с locale, шириной, темой и именем figure. Проверить изображение глазами: spinner, перекрытие header, обрезанная подпись или неготовый шрифт означают отклонённый QA-снимок. Исправить готовность/прокрутку и переснять; это не основание менять доказательные native-пиксели.
5. Считать отдельно: 18 комбинаций × пять целей = 90 browser-QA PNG. Это выборка представления статьи, не 90 новых Figma captures и не просмотр всех видео. Не присваивать всей статье визуальный pass только по количеству файлов.

### B. Обязательное визуальное чтение и воспроизведение

1. Открыть **собранную страницу**, не только отдельный PNG. Для RU/EN/ZH проверить desktop 1440 px, mobile 390 px и 320 px в light и dark: 18 сочетаний.
2. Скриншоты прочитать глазами: назвать конкретный текст/родителя/результат, который зритель должен различить. Проверить поля, обрезание, размер и контекст. Геометрия без overflow не означает читаемость.
3. Каждый из 21 локализованных роликов проиграть от начала до конца при 1× на desktop. Для каждого сочетания mobile/theme проверить inline-представление и воспроизведение; особенно короткие подписи, ввод, момент переноса и последнюю паузу. Не выдавать контактный лист или три извлечённых кадра за просмотр видео.
4. На каждой ширине проверить ручной старт, pause/resume, достижение конца, poster, отсутствие autoplay и loop. GIF — отдельная добровольная загрузка, не автоматически движущийся дубль.
5. Проверить раскрытие: правильный тот же файл, fit/original/zoom, пропорции, сохранение playback position и play/pause при смене масштаба; Escape закрывает, видео останавливается, фокус возвращается. Проверить клавиатуру, reduced motion и понятную ошибку загрузки.
6. Проверить, что комментарии/персонажи не перекрывают native-пиксели и не перехватывают media-триггер. Тёмная тема не должна делать подписи неразличимыми.
7. Записать отдельно, какие сочетания просмотрены и какие результаты получены. Если что-то не просмотрено, назвать это ограничением, а не «всё проверено».

## 10. Принятие или пересъёмка

### Принять новый материал можно только если

- [ ] Реальный Figma-источник, безопасная QA-копия и происхождение установлены.
- [ ] До → действие → после видны; формулировка не обещает отсутствующее доказательство.
- [ ] Сохранены инварианты выбранного сценария и оригинальные диагностические примеры.
- [ ] Нативный текст и нужный контекст читаются, нет случайного toast/обрезанных контролов.
- [ ] Новая запись содержит реальные паузы ≥ 2 с до и ≥ 3 с после, адекватный посимвольный ввод и понятные подписи.
- [ ] Непрерывность, скорость, crop, курсор и Cut/Paste описаны честно; нет синтетических UI-состояний.
- [ ] Кропы воспроизводимы; в metadata реальные даты, хеши, размеры и координаты.
- [ ] MP4, GIF, poster, manifest и HTML согласованы; нужные версии прошли staged и итоговые проверки.
- [ ] Ролики действительно просмотрены, изображения прочитаны в указанной browser-матрице; технический pass не подменяет этот этап.
- [ ] Отчёт перечисляет выполненные проверки и ограничения без «полная QA» по узкому тесту.

### Отклонить и исправить источник/дубль, если

- финальный текст появился мгновенно, но заявлен набор; действие выполнено API вне кадра, но заявлен UI-процесс;
- вместо непрерывной записи получилась последовательность PNG, скрытая склейка или искусственные паузы;
- имя слоя выдано за продуктовый текст, перестановка — за reparent, source — за local target, Show target — за открытие модалки, Ready — за готовое приложение;
- важный UI мелкий из-за пустого полотна, обрезан, перекрыт подписью или нечитаем на целевой ширине;
- подпись опережает действие, меняется до прочтения или описывает другой QA-контекст;
- результат отсутствует, pause-after слишком короткая, в середине поиск/ошибка/постороннее ожидание;
- старым данным присвоены сегодняшняя дата, новые capture-count или чужие результаты тестов;
- тест зелёный только после удаления проверки, подмены хеша без аудита либо игнорирования фактического source.

**Порядок исправления:** понять причину → поправить постановку кадра/сценарий → переснять при необходимости → снова stage → снова технический и визуальный контроль. Не маскировать проблему постобработкой.

## 11. Объясняющие схемы и инфографика

Схема показывает **связь или решение**, а не доказывает работу Figma, плагина или приложения. Не рисовать похожий на настоящий интерфейс и не выдавать его за скриншот. Не добавлять картинку в каждый справочник ради наличия картинки.

### Карточка схемы — заполнить до отрисовки

```text
Вопрос читателя: что именно он пока не может связать?
Правило: путь и раздел канонической документации.
Объекты: только участники нужной связи, с точными идентификаторами.
Связь: вложенность / соответствие / последовательность / ветвление.
Как читать: откуда начать, куда ведёт каждая стрелка, что проверить в конце.
Вывод: одна фраза, которую можно понять без изображения.
Граница: пример, а не норма; дизайн-намерение, а не runtime-доказательство.
Локали: EN, RU, ZH — включая видимые подписи, title, desc и alt.
```

### Сделать и встроить

1. Прочитать абзац до картинки и после неё. Проверить, что показаны именно названные объекты. Если код содержит `home`, а рисунок — отдельный `workshop`, явно назвать его отдельным примером того же правила.
2. Найти подходящий builder в `scripts/build-tutorial-diagrams.mjs`. Сначала улучшить или переиспользовать его. Не создавать второй renderer и независимую копию правила в картинке.
3. Выбрать геометрию по смыслу: родитель содержит детей; соответствие соединяет те же элементы; стрелка процесса имеет начало и результат; ветвление подписано условием. Цвет не должен быть единственным носителем различия. Не заменять отношения стопкой длинных текстовых карточек.
4. Сначала написать короткие подписи во всех трёх языках. Машинные ключи, теги и значения не переводить. Разбить длинную фразу на строки или вынести подробность в подпись статьи, а не уменьшать шрифт. Для новых вертикальных схем использовать компактный холст около 480 px и основной текст 24–26 px; эти размеры **не гарантируют** читаемость после уменьшения браузером.
5. Генератор создаёт native draw.io XML, затем экспортирует SVG с редактируемым графом. Собирать только изменённые концепты, например `node scripts/build-tutorial-diagrams.mjs scope roles`. Не править экспорт одного языка вручную. Для четырёх расширенных концептов одновременно обновляются старые английские SVG/PNG URL.
6. В статье использовать локализованный SVG и существующий `bridge-lesson-figure`, содержательный `alt`, фактические `width`/`height`, подпись и ссылку на полный размер. В `docs/zh/` и `docs/ru/` путь к assets начинается с `../../assets/`. Заголовок схемы не заменяет пояснение её вывода и границы в тексте статьи.
7. Сверить подпись с рисунком: дерево не показывает два breakpoint; хороший пример не является сравнением «до/после»; локальная цель не доказывает открытие окна; список тем не является покрытием валидатора. В частности, `Partial` объяснять конкретной незакрытой зависимостью примера, а не объявлять свойством любой секции.

### Проверить перед коммитом

- Запустить `npm test` и `npx playwright test tests/diagram-readability.spec.mjs`. Проверки должны охватывать локализованные assets и реальные размещения в статьях, а не только одну демонстрационную страницу.
- Открыть готовые статьи в EN/RU/ZH на 1440, 390 и 320 px, в светлой и тёмной теме. Прочитать основную связь **в обычном масштабе**. Проверить стрелки, переносы, контраст, отсутствие обрезанного текста и совпадение подписи с изображением. Детали могут требовать увеличения, основной вывод — нет.
- Открыть увеличенный просмотр с клавиатуры, закрыть Escape и проверить возврат фокуса. Текст статьи должен оставаться полезным, если изображение не загрузилось.
- Отклонить схему, если она обещает общий Ready/WCAG-pass по проверке исходного макета, скрывает условие или исключение, содержит другой язык либо читается только после увеличения. Исправить источник и снова экспортировать все три локали.
- Отдельно записать фактически выполненный визуальный просмотр и автоматические проверки. Наличие SVG, верных размеров и зелёного теста не является редакторским одобрением.
